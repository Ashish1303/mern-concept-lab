# Editable snippets — review report

Status **APPROVED_COMPLETE**. The user explicitly approved the enhancement and Phase 3 before authorizing Phase 4 on 2026-11-09. The evidence below covers the original 451 views. See [Phase 4 coverage](PHASE_4_COVERAGE.md) for the additional 54.

## What changed

Every existing example now has visible editable code above its original demonstration. Coverage is 451 editor views: 449 distinct curriculum examples (331 JavaScript/TypeScript and 118 React) plus two foundation checks. Mandatory example aliases resolve to the same editor rather than duplicating implementations. Future curriculum placeholders remain unimplemented.

The starting snippet comes from the actual lesson source. It includes the selected function, relevant imports and required local declarations, without lesson metadata or unrelated examples. Thin React wrappers open their actual supporting implementation. The Code file selector also lets learners edit supporting files. Run compiles the current draft and runs the changed code; it does not rerun a fixed implementation or copy expected output. The original demonstration, complete read-only source, explanations, mistakes and interview questions remain available alongside it.

Run, Reset and Stop are keyboard-accessible native controls. Reset restores the original code, supporting files and input, clears results/errors and ends active work. Stop removes the preview, aborts its requests and terminates active compilation. Edits remain in memory for the selected example, including during search changes. Switching examples or refreshing starts from the original code; there is no automatic server or browser-storage saving of drafts. A notice identifies edits that have not run.

## Execution and TypeScript

- 411 views execute browser code: 291 language runtime examples, 118 React components and two foundation components. React previews use the actual production React SDK and retain their own state, effects, DOM, controls and traces. They do not inherit the application's development StrictMode replay.
- 40 views are compiler exercises. They expose the existing deliberately invalid statements and run the real TypeScript 6.0.3 checker in a Worker, using the installed public library declarations and fixture compiler options. Learners can correct errors and run again. These fixtures can reference React, Node, Express, Redux Toolkit or Mongoose types without executing server code or connecting a database.
- Runtime snippets compile TS/TSX syntax to JavaScript; they do not promise full semantic type checking. Compiler exercises explicitly provide that separate mode. Syntax errors include real compiler diagnostic codes and positions; runtime errors appear in the error panel. Full build-time compiler evidence remains a separate reference panel.
- Supporting imports use the supplied lesson files and the existing React, React DOM and Redux Toolkit libraries. Arbitrary new package imports are not installed. The typed Redux store is an existing Phase 2 example, not implementation or approval of the later Redux curriculum.

The compiler is loaded lazily in a dedicated browser Worker. Generated assets contain only public installed declarations/package metadata and owned fixture sources: 302 files, about 8.2 MB uncompressed. They are generated by build:playground and ignored by Git. The editor itself is lazy-loaded; the main application does not eagerly execute or bundle the compiler into its initial application code.

## Isolation and lifecycle

Edited code is never evaluated by Express or in the application's document. A separate loopback origin serves the trusted preview runtime: by default http://127.0.0.2:4001, with the app/API on 127.0.0.1:4000. PLAYGROUND_PORT defaults to PORT + 1 and can be set explicitly. The preview binds only to 127.0.0.2. This is a local development/review feature; externally hosted previews need an explicit hosting design in a later authorized phase.

The application retains its self-only script policy and embeds only the configured preview origin. The preview has its own policy: no direct connections, Workers, objects or native form submissions; scripts are limited to the trusted runtime and compiled Blob scripts. It cannot read the application document. No unsafe-eval is enabled. User code and drafts stay in the browser; no online compilation service is contacted.

Real API examples use a message bridge that validates the current frame, origin and run channel. It accepts only the existing fixed health/items/ack paths, bounded GET/POST bodies and responses, and omits credentials. The requests reach actual Express routes; there is no simulated backend. Stop, Reset, another Run and navigation abort owned requests, and old frames/compilers cannot publish stale results into a new run.

Loops, recursion and callback chains receive checkpoints. Runtime functions have a three-second deadline even if their returned promise ignores cancellation; compilation can be stopped and has a 30-second deadline. React previews remain interactive until stopped or replaced. These controls address ordinary accidental hangs; they are not a general-purpose hostile-code or memory quota service.
